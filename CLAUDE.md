# CLAUDE.md

Guidance for working in this repository — the Arise Association church/event website.

## Architecture

**Backend (repo root, CommonJS)**
- `server.js` — Express 4 + `mysql2/promise` connection pool.
- Serves the production React build from `/public`.
- Endpoints:
  - `GET /health` — health check (checks DB connectivity).
  - `POST /api/volunteers` — volunteer registration (rate-limited, validated, parameterized INSERT).
  - `GET /api/volunteers` — admin-only paginated list (`x-admin-key` header, rate-limited).
  - `GET /api/volunteers/summary` — admin-only role counts (`x-admin-key` header, rate-limited).
- Middleware: Helmet (CSP enabled), `express.json({ limit: '20kb' })`, optional CORS via `CORS_ORIGIN`.

**Frontend** (`arise-site/` — ESM, React 19 + Vite 8)
- Routes: `/` (landing, `AriseCommunitySite.jsx`), `/volunteer` (form, `VolunteerForm.jsx`), `*` (404).
- Vite builds directly into **root `public/`** (`build.outDir: '../public'`).
- Env (read from `arise-site/.env`, only `VITE_*` exposed to browser):
  - `VITE_API_URL` (default `/api`), `VITE_HERO_VIDEO_URL`, `VITE_PROMO_VIDEO_URL`.

**Database** (`db/`)
- `schema.sql` — canonical `volunteers` table definition.
- `init.js` — idempotent, non-destructive initializer: `CREATE TABLE IF NOT EXISTS` + indexes. Run with `npm run db:init`.

## Commands

| Command | Purpose |
|---------|---------|
| `npm install` | Install root deps (postinstall installs frontend deps and builds) |
| `npm run build` | Build the React app into root `public/` (single reproducible command) |
| `npm run db:init` | Ensure DB schema/indexes exist (idempotent, safe) |
| `npm start` | Start the production Express server (serves `public/`) |
| `npm run lint` | Run oxlint on the frontend |
| `npm --prefix arise-site run dev` | Vite dev server with HMR |

## Build pipeline

```
npm install          # root + frontend deps
npm run build        # Vite → root public/ (React production build)
npm start            # Express serves public/ + API
```

The build output in `public/` is **gitignored** and regenerated by `npm run build` — never commit it.

## Environment variables

See `.env.example`. Key values (set as real env vars in Hostinger hPanel, or in `.env` locally):

| Variable | Required | Notes |
|----------|----------|-------|
| `ADMIN_API_KEY` | Yes | Server-only. Never put in `VITE_*` or client code. |
| `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` | Yes (unless using `DATABASE_URL`) | Hostinger MySQL credentials |
| `DATABASE_URL` | No | Full `mysql://` URL; overrides `DB_*` |
| `PORT` | No | Hostinger sets this automatically |
| `NODE_ENV` | No | Defaults to `production` |
| `DB_POOL_MAX`, `DB_POOL_IDLE`, `DB_POOL_IDLE_TIMEOUT`, `DB_POOL_QUEUE_LIMIT` | No | Pool tuning |
| `CORS_ORIGIN` | No | Comma-separated allowed origins; only needed if frontend/API are separate origins |

Frontend-only vars go in **`arise-site/.env`** (e.g. `VITE_API_URL=/api`, `VITE_HERO_VIDEO_URL=/videos/hero.mp4`, `VITE_PROMO_VIDEO_URL=/videos/promo.mp4`).

## Hostinger Business (managed Node.js) deployment

1. Push the repo to GitHub.
2. In Hostinger hPanel → Websites → **Node.js** → create a Node.js app (Node 20+).
3. Set environment variables in hPanel (Application Settings):
   - `ADMIN_API_KEY` (long random string)
   - `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` (from hPanel MySQL databases)
   - `NODE_ENV=production` (Hostinger sets `PORT` automatically)
4. **Application root**: repo root (where `server.js` and `package.json` live).
5. **Build command**: `npm install && npm run build && npm run db:init`
6. **Start command**: `npm start` (runs `node server.js`).
7. Deploy from GitHub (hPanel Git integration) or upload via File Manager. The app is same-origin — the frontend served from `public/` calls `/api/*` on the same host, so no CORS needed.
8. Visit `/health` to verify DB connectivity.

Hostinger runs Nginx as a proxy to the Node process — the frontend and API share the app's public origin, so the production API URL is just `/api` (no hardcoded localhost).

## Docker (optional second deployment option)

For local development/testing, or a future VPS:

```sh
cp .env.example .env   # fill in real values
docker compose up --build
```

- `Dockerfile` — multi-stage: builds the React app, then a production `node:20-alpine` runtime with a non-root user and a healthcheck.
- `docker-compose.yml` — `app` + `mysql:8.4` services with named volume, healthchecks, and env-file driven config. No secrets committed.
- MySQL data persists in the `arise-db-data` volume. The DB is initialized from `db/schema.sql` on first boot (safe, non-destructive).
- Do not commit `.env` — it is gitignored.

Docker is an **additional** option; Hostinger Business managed Node.js does **not** require Docker.

## Scaling

The app is **stateless**:
- No in-memory sessions, no local file uploads, no global mutable state.
- Uses a configurable MySQL pool (`DB_POOL_MAX`) — never one connection per request.

Future scaling path (documented, not implemented):
```
Load Balancer → multiple Node/Express containers → MySQL
```
- Rate limits are per-instance (in-memory store). For multi-instance deployments, migrate to a shared store (e.g. Redis) via `rate-limit` store adapters.
- Use `DB_POOL_MAX` proportional to connections each instance may hold.

## Security rules

- **Never** put credentials/secrets in client code, `VITE_*` vars, or commit them to the repo.
- `ADMIN_API_KEY` stays server-side, compared with a constant-time comparison.
- All SQL is parameterized; never concatenate user input into queries.
- Keep the request body limit small (`20kb`) — it must stay small.
- Do not disable Helmet or remove the CSP. Update CSP directives in `server.js` only when the site gains exposed external origins.
- Public submission endpoints are rate-limited; admin endpoints are rate-limited + key-protected.
- Re-run `npm audit` after dependency changes.
